# 锚点数优先、照片数其次：修改与验收计划

日期：2026-10-24。状态：已实施两阶段求解、基线兜底、schema 5、新旧方案对照及高密度复核重选；见[验收报告](lexicographic_anchor_selection_validation_20261024.md)。

目标及前期分析见[热力图选点与观察模型加速讨论](heatmap_selection_and_observation_acceleration_20261023.md)。本计划先解决选择目标和求解质量，完成验收后再进入观察模型加速。

## 1. 固定目标与承诺边界

全部输入物体至少被一个合格拍摄动作覆盖，作为硬约束。资源成本按以下顺序比较：

```text
cost(plan) = (不同站位数量 K, 定向拍摄动作数量 P)
先比较 K；只有 K 相同才比较 P。
```

同一站位三个方向算一个锚点、三张照片。合格定义沿用现有入镜、遮挡、像素及得分门槛，不通过放宽门槛来减少成本。没有额外的照片预算、每站方向上限或导航成本。

“得到更优的解”分成三项可验证要求：

1. **不退步：** 同一候选关系、相同覆盖前提下，新输出的 `(K,P)` 不劣于现有贪心结果。
2. **严格改进：** 对已有非最优反例得到更小的 `(K,P)`；默认地图如存在可发现的改进，应实际输出并报告。
3. **证明最优：** 两阶段都完成最优性证明，才标记当前有限候选池下的字典序最优。

不能事先保证每张地图都严格减少锚点或照片：旧解可能已经最优。默认地图此前为 `(5,14)`、28/28 合格覆盖；如果它已经最优，获得证明也属于第一阶段的有效成果。限时找到等价可行解但没有证明，不能称为完成“更优或已证最优”的质量验收。

## 2. 本轮实现范围

保留安全区域、全部安全格中心、朝向网格、相机参数、观察模型、候选 supports/scores、逐物体热图和最终动作几何复核。首轮不改变遮挡采样，不缩减位置/方向网格，不增加质量奖励目标，不实现导航。

修改集中在“已有合格关系 → 选择站位与动作 → 输出与解释”这一层。用同一份 `CandidateResult` 比较旧新选择器，避免观察模型变化干扰结论。

使用当前环境已有的 SciPy 1.15.3 `optimize.milp`（HiGHS），不额外引入求解器依赖。本次已核对本机签名及对应版本文档：接口提供整数约束、时间限制、解状态和 gap，但没有公开的初始整数解参数。因此旧贪心方案作为外部兜底和目标上界使用，不声称已传入求解器作热启动。[SciPy 1.15.3 官方接口](https://docs.scipy.org/doc/scipy-1.15.3/reference/generated/scipy.optimize.milp.html)

## 3. 步骤一：建立基线和独立的覆盖问题表示

### 3.1 保留旧算法作为基线

将现有 `select_anchors()` 的加权贪心实现保留为显式的 `select_anchors_greedy()`，算法行为不变。新默认入口仍使用 `select_anchors()`，由其协调新求解器、结果校验和旧方案兜底。

对同一个候选结果先计算旧方案，记录：覆盖物体 ID、锚点数、照片数、站位及方向、求解耗时。旧基线不会与新求解器共用可变集合，防止一个求解器修改另一个的输入。

### 3.2 新增独立求解模块

新增 `falhv2/anchor_optimizer.py`，只接收候选站位索引、合格方向关系和目标 ID；返回选中的 `(station_index, yaw_index)` 与求解状态，不依赖相机、页面或地图几何，避免循环导入。

建议职责划分：

| 接口职责 | 输入/输出 |
|---|---|
| 构造覆盖问题 | 构造稳定索引、二值站位覆盖、二值动作覆盖及动作所属站位 |
| 求最少锚点 | 返回可行站位集合、整数目标、下界和证明状态 |
| 固定锚点数求最少照片 | 返回实际站位/动作集合及照片目标的证明状态 |
| 验证与成本比较 | 校验整数解、覆盖、站位关联，并按 `(K,P)` 比较 |

候选评分仍保存，但不进入主要优化目标。只排除完全没有合格支持的站位和方向；使用稀疏矩阵表示约束。首版不按热图分数做 top-k，也不按站位覆盖并集合并或删除第二阶段候选。

### 3.3 先做全覆盖可行性检查

- 空目标直接返回零锚点、零照片，保留 `empty_targets`。
- 有物体在所有候选动作中都没有支持：全覆盖在此池内不可行。保持 `partial` 及缺口 ID，保留基线的部分覆盖用于诊断，本轮不另行定义部分覆盖优化目标。
- 全部物体各自有至少一个支持：在当前没有资源上限的模型中，取所有相关动作必然可覆盖，所以后续模型若报告不可行，应检查建模、约束或数值错误，不应直接归因于地图无解。

## 4. 步骤二：精确求最少锚点数

对每个有支持的站位定义二值变量 `x_p`；令 `C[o,p]=1` 表示该站至少有一个合格方向能观察物体 o。

```text
minimize Σ_p x_p

subject to
    Σ_p C[o,p] × x_p ≥ 1       对所有输入物体 o
    x_p ∈ {0,1}
```

因为本轮不限制每站拍摄方向数，站位覆盖并集能准确表达第一目标：选中某站后，总能选择足够多的合格方向实现它的并集覆盖。

用已验证旧方案的 `K_old` 添加安全上界 `Σx ≤ K_old`。不固定旧站位，也不把搜索限制在旧站位附近。

设置整数变量上下界为 0、1，设置 `mip_rel_gap=0`，保留求解器的数值容差语义。返回后验证变量足够接近二值、解码后的集合覆盖全部物体、实际站位数与目标值一致，不能把一般连续松弛解直接四舍五入当作可行解。

第一阶段证明最优后得到 `K*`。按该站位集合生成一个完整的可行照片方案作为第二阶段兜底；可以使用现有照片贪心，或先取能覆盖全部目标的方向并集。这只是保底方案，不是第二阶段的搜索范围。

## 5. 步骤三：在最少锚点数下联合优化照片

对所有合格候选动作 `a=(p,θ)` 定义二值变量 `y_a`，同时保留所有有支持站位的 `x_p`。令 `B[o,a]=1` 表示该动作能合格观察物体 o。

```text
minimize Σ_a y_a

subject to
    Σ_a B[o,a] × y_a ≥ 1       对所有输入物体 o
    y_(p,θ) ≤ x_p              拍照动作必须属于被选站位
    x_p ≤ Σ_θ y_(p,θ)          被选站位至少实际拍一张照片
    Σ_p x_p = K*               固定最少锚点数量
    x_p, y_a ∈ {0,1}
```

**这一步必须重新允许选择所有候选站位。** 固定第一阶段某组站位、只在那组站位内选照片，会错过同样 K* 个锚点下更省照片的另一组站位。

第二阶段可用“已经验证、实际使用 K* 个站位的照片方案”提供 `Σy` 上界。如果新 K* 比旧锚点数更小，不能无条件用旧方案的照片数作上界：更少的站位允许需要更多照片，这仍符合优先级。

完成证明后得到 `(K*,P*)`。首版不添加连续得分或编号的微小权重，以免不慎改变主目标；相同最优成本下可能存在多个正确站位集合。输出按原站位/方向编号排序，但不承诺跨求解器版本选中完全相同的等价最优集合。

## 6. 步骤四：不退步保障、状态与限时行为

### 6.1 候选方案管理

维护已经验证的最佳可行方案，初始为旧贪心结果。每得到一个新方案，先检查集合覆盖及站位/动作一致性，再按 `(K,P)` 比较；只保留更小的成本，相同成本可保留已有方案以减少无意义变动。

最终方案继续通过 `plan()` 现有的逐动作、逐物体观察模型复核。若新方案复核失败，不得标为成功；保留错误信息，并使用通过同等验证的旧方案作为兜底。若旧方案也不能通过复核，直接报错。

第一轮默认不设置人为求解时间上限，以便离线研究尽量获得证明；仍明确整数优化可能耗时较长，不以限定秒数作为本轮交付目标。CLI 为可选 `--selection-time-limit-s`，含义为全部 MILP 调用的总时间预算（包含实施补充中的复核重选），不包含候选生成、基线计算和最终几何复核。

### 6.2 限时与异常处理

| 情况 | 输出策略与表述 |
|---|---|
| 两阶段都证明最优 | 输出最优成本，标为有限候选池下字典序最优 |
| 第一阶段证明、第二阶段限时 | 输出最好的已验证可行解；锚点数最优，照片数尚未证明 |
| 第一阶段限时但有新可行解 | 用剩余预算在其锚点数量下改善照片；两级全局最优性均不宣称 |
| 限时没有新可行解 | 使用旧方案，记录未获得改进及求解界限 |
| 新方案不如旧方案 | 保留旧方案，记录新候选被拒绝的原因 |
| 求解报错或返回不可验证变量 | 记录错误并使用已验证基线；不能将错误解释为证明不可行 |

如果第一阶段未证明最优，第二阶段的照片最优也仅是“给定当前锚点数”的条件最优。完整字典序最优需要两阶段条件同时满足。限时模式的输出可用于研究，但不能绕过后面的质量验收。

## 7. 步骤五：结果格式和可视化同步

### 7.1 输出字段

计划将主规划结果升级为 schema 5，保留 `anchors`、`observations`、`score_by_object`、`object_metrics`、覆盖缺口及候选统计。新增结构化信息：

```text
selection_method: lexicographic_milp 或 weighted_greedy_fallback
objective_order: [anchor_count, photo_count]
baseline_cost: [K_old, P_old]
selected_cost: [K_new, P_new]
comparison_to_baseline: improved / equal
optimization:
    scope: finite_station_yaw_pool
    stage1: 状态、目标值、下界、gap、耗时、锚点最优性是否证明
    stage2: 状态、目标值、下界、gap、耗时、照片最优性是否证明
    lexicographic_optimal: true/false
    fallback_reason: ...
```

保持覆盖状态与最优性状态分离：`complete` 只表示全部物体合格覆盖，不表示最少站数。部分覆盖、空目标另有明确适用范围，不能误用全覆盖最优标签。阶段字段也要能表达未运行、失败或没有有效界限。

完整候选 supports 文件的含义没有改变，可保留 schema 4，单独说明其与主结果 schema 的版本独立；如添加字段改变其结构，再显式升级。不要因为主结果升级就默默改变候选文件语义。

### 7.2 页面

- 保留逐物体最佳分数热图及全部物体的静态叠加图，作为观察能力展示。
- 明确显示旧新成本、覆盖状态、各级最优性及是否使用兜底。
- 新解没有贪心选点顺序：不填造 `vote_trace`，不绘制“下一轮选点”箭头或把编号解释为访问顺序。
- 旧贪心回放只在单独的“基线对照”视图中展示；切换新旧方法时重置动作选择、热图轮次等状态。
- `viewer_data()` 必须传入新结果的选择方法和优化状态，不能继续硬编码“物体观察权重叠加”作为选择算法名称。

代码依赖已核对：当前 HTML 的 `completedObjects()`、`buildHeatmap()` 和 `draw()` 直接读取 `vote_trace`；这三处及工具栏需要按求解方法区分，不能只替换 Python 选点函数。

## 8. 步骤六：正确性与更优解验收

### 8.1 必须新增的求解器测试

| 测试 | 验收结果 |
|---|---|
| 已有 A/B/C/D/E 六目标反例 | 旧方案 3 站，新方案 2 站、2 张，全覆盖 |
| 同站位覆盖并集、不同方向组织 | A 用三个方向覆盖全部目标，B 用一个方向覆盖同样目标；求解必须选到 1 站、1 张，不能固定第一阶段的 A |
| 锚点数优先于照片数 | 可选 1 站3张 或 2 站2张时，选择 1 站3张 |
| 分数不覆盖成本优先级 | 低分但合格的较低成本方案优于高分的较高成本方案 |
| 极小实例穷举核对 | 枚举最多约 12 个动作的所有子集，独立求最小 `(K,P)`，与两阶段结果一致 |
| 非连续站位编号 | 输出正确映射回原始站位与方向索引 |
| 空目标、无支持目标 | 明确空结果或缺口，不伪造全覆盖 |
| 限时、空解、求解异常 | 正确保留基线，状态不误报最优 |
| 数值/解码校验 | 拒绝非整数、覆盖缺失、无照片的计数站位等错误结果 |
| 相同目标多个最优集合 | 比较成本与覆盖，不把某个任意坐标集合写成唯一正确答案 |

现有强制断言“加权贪心选点轨迹”的测试改为显式测试 `select_anchors_greedy()`；它们仍有基线价值。默认新选择器测试断言资源目标与合格覆盖，不能删除旧测试后只验证返回格式。

独立穷举直接基于动作子集、覆盖集合与实际不同站位数计算，不复用 MILP 建模逻辑，避免两个实现犯相同错误。

### 8.2 默认地图与集成验收

1. 固定输入哈希、站位池、方向网格、观察参数，重建并保留一份完整候选关系；旧新求解共用该关系。
2. 核实旧基线是否仍为 `(5,14)`、28/28；输入变动时使用新的实测基线，不能拿不一致输入比较。
3. 报告新 `(K,P)`、每阶段上下界、gap、时间及证明状态。
4. 最终每张照片独立几何复核，全部原始目标合格覆盖；主 JSON、HTML、SVG 和支持关系一致。
5. Python 全套测试及两组 Node.js 交互测试通过；检查新旧视图、空目标、缺口和兜底状态。
6. 针对最终新动作补做高密度遮挡审计，单独记录与原采样规则的差异。若有分类翻转，报告观察模型精度问题，不能只在最终动作上换门槛却仍声称对原矩阵的优化结果可直接执行。

### 8.3 进入加速阶段的门槛

第一阶段交付必须满足：反例严格改善、极小穷举对照一致、默认地图全覆盖且资源成本不退步，并取得“默认地图严格改进”或“旧成本已被证明最优”的有效结论。

目标仍是让默认地图两级都获得最优性证明；若只获得严格改进但证明未完成，需要明确标记剩余界限。若既没有严格改进也没有证明，则继续解决求解质量与证据问题，不通过缩小候选池或降低观察精度来宣称完成。

## 10. 第二阶段：在合格关系不变的前提下加速

质量验收完成后，以新求解器和固定候选关系作为基准，依次做：

1. 入镜/面积上界等几何门槛前置，避免必然失败观察的射线计算，并设计失败诊断补算。
2. 粗细采样共享几何结果，批量计算距离权重，缓存采样网格和位姿。
3. 再优化射线与裁切内核，评估合理批量和并行。

每项都比较完整 supports、分数、整数票及新求解成本，而不只比较最终覆盖率。不将减少方向、粗化站位、减少采样或放宽门槛混入“等价加速”。新旧 `(K,P)` 不变或差异有完整解释，观察合格性保持，才接受性能结果。

本轮首先接受“计算仍约一分钟甚至加上更长求解时间，但方案更省锚点/照片并有可检查证据”的结果。性能目标在正确性和解质量确认后单独制定。

## 实施补充：完整模型与等价化简

默认地图的直接照片模型含 84,029 个变量。补充了由整数可行性蕴含的站位覆盖约束，增强 LP 松弛后，完整模型取得 `(4,10)`、两级 gap 为 0 的证明。

为消除等价组合，再加入求解层的精确化简（观察模型不变）：同站去除覆盖集合被其他方向包含的动作；再按所有极大动作覆盖集合组成的完整族合并等价站位。代表站位保留真实位置及方向，任何被替代照片都有同站或等价站的合格覆盖超集可替代，锚点数和照片数均不增加。全局最少锚点方案不需要重复选择等价站，因此字典序最优成本保持。不能仅按站位的覆盖并集合并。

默认地图由 10,644 个站位、73,385 个有支持动作，形成 1,281 个代表站位、5,900 个代表动作；完整 supports 和热图不删减。化简后模型独立得到同样的 `(4,10)` 证明，另外通过小实例动作子集穷举核对。上述化简不适用于日后加入路径、转向、站位个别成本或质量优化的目标。

## 实施补充：高密度复核发现缺口后的重选

首次 `(4,10)` 解中的 `station=2013, yaw_index=9, object=o14` 在原 36×36 临界采样下得分 0.502468，96×96 下变为 0.497234，低于相同的 0.5 门槛。不能把这个解直接作为已通过验收的全覆盖方案。

因此在最终动作上增加至少 96×96 的独立复核，不修改原观察代码、门槛、完整 supports 和热图。若出现覆盖缺口，在求解专用副本中删除已检查动作被复核否定的支持关系，再从全部候选重新求解，最多三次，所有求解调用共享时间预算。最终动作仍必须通过原模型复算，并保留两种采样的独立指标。若不能修复，只能退回通过高密度复核的旧基线；基线也未通过时明确报告失败，不声称完成可靠覆盖。

**证明的传递条件：** 原矩阵已经证明的最优成本为 `(K*,P*)`。只有重选方案仍是原矩阵的可行解、成本恰为 `(K*,P*)` 且通过复核，才保持原候选池最优标签。删边后子问题的最优性本身不能证明原矩阵最优；成本变大时必须标为原候选池最优性未证明。本例一次重选后仍为 `(4,10)`，满足条件。

这仍不是全部候选在 96×96 下重新生成覆盖矩阵后的最优性证明。高密度计算只验证最终动作，也不能消除所有几何采样误差或代替实拍验证。此补充用于完成本轮解质量验收，观察模型加速尚未实施。
