# FALH-V2 实施进度与下一步

更新：2026-10-15。研究定义、两条候选生成路线及观察模型见[锚点选择文档](path_constrained_anchor_selection_v0_20261013.md)。当前 A1 已完成，A2/A3 的物体驱动算法已通过 `falhv2/anchor_selector.py` 接入 `main`，独立于实验目录；下一步验证实际采集并改进照片选择。位置采样仅保留在 `experiment/anchor-candidate-drivers` 实验分支。详见[首轮实验报告](anchor_driver_experiment_20261014.md)。

## 已完成

- [x] [地图编辑器](../../falhv2/README.md)：绘制栅格和无类别物体中心点，支持大图、缩放、平移、笔刷与矩形填充。
- [x] [A1 路径规划器](../../falhv2/path_planner.py)：只输入地图、机器人长宽与安全距离，采用 EDT 障碍膨胀、OpenCV 四连通标记、区间分解与往复扫描、A* 分区连接；不要求起终点。
- [x] 输出各区域安全格、连续四邻接路线、世界坐标航点、长度与转向统计；检查覆盖和净空，SVG 合并重复图元以减轻大图显示负担。断开区域分别输出，无安全格时明确失败。
- [x] 在 `main` 接入生产规划器，不依赖实验模块；使用 conda `test` 环境，A1 依赖 NumPy、SciPy、OpenCV。
- [x] 通过 `config.py` 统一管理路径：当前地图、机器人、相机从 data 读取；可重新生成的产物写入 Git 忽略的 outputs，备份目录 outputs_ 同样忽略。路线测试使用代码内的固定小地图，不依赖用户数据。
- [x] 确定站位与定向拍摄分开计数，主要减少站位、其次减少照片；锚点数由算法输出，无预设数量预算。

A1 只验证可通行区域与路线，尚未验证物体视觉覆盖；区域与路线统计以对应输入和实际输出为准。

## A2 已接入主线：物体驱动观察模型与候选生成

### 共用模型与数据

- [x] 实现 [D435i 标定导出脚本](../../falhv2/camera_parameters.py)，通过 conda `test` 中的 `pyrealsense2` 读取真机 RGB 1280×720、30 FPS 内参与畸变信息；读取结果保存于本地 outputs，与 `falhv2/data/camera.d435i.json` 使用相同精简结构；用户人工补全 `null` 标记的安装位姿和有效观察距离后，自行放入 data 作为默认参数。尚未验证实际图像采集，安装外参与有效观察距离待测量。
- [x] 实验分支保留 200×200、28 个物体点的固定快照；主线使用编辑器保存的 `data/map.json`，不再复制实验地图。
- [ ] 确认相机图像尺寸、内参或视场角、相对底盘的位置与朝向、去畸变状态、允许拍摄动作。首版固定安装高度和俯仰，通过底盘原地转向拍摄。当前配置已由用户填写安装位置 `[0.23,0,0.5]` m、零安装角和 0.2–3 m 距离，实际采集条件仍待确认。
- [x] 在 `anchor_selector.py` 建立 `q(i,θ,o)`：动作可执行、相机坐标变换、前后关系、水平/垂直视场、距离及物体点高度。首版不要求物体尺寸或 AABB，不计算像素宽高；将结果称为视场和距离条件下的预计覆盖，不声称真实成像质量达标。
- [x] 首版遮挡标为未评估；二维导航障碍和膨胀图不直接用于三维相机遮挡。
- [x] 定义共用结果：站位 ID、区域与路径索引、拍摄方向、稀疏覆盖关系、逐物体支持集合、覆盖缺口和内部配置。重合站位按物理位置去重。

### 已完成选型

| 路线 | A2 候选与覆盖构建 | A3 选择与优化 |
|---|---|---|
| 物体驱动，main 正式入口 | 每个物体反向生成合格观察位置/方向集合，与 A1 路径相交；首版离散表示，粗筛后用共用模型验证 | 动态投票 / 贪心集合覆盖，删冗余站位，再减少照片 |
| 位置驱动，仅实验分支 | 路径均匀或随机采样，枚举方向，正向检查能观察哪些物体，对缺口局部补点 | 使用同一求解器，便于比较候选生成差异 |

- [x] 物体驱动：距离等保守界限筛出附近路径点，计算允许方向；不要用近似粗筛漏掉合格候选。
- [x] 位置驱动：均匀采样作基线，随机采样记录抽样方式与种子；需要多个种子评估波动。此方法借鉴采样思想，不等同于生长运动树的 RRT。
- [x] 对缺口按嵌套位置池加密，另外完成 30°/15° 方向敏感性实验；记录加密次数与资源限制。随机点多不构成全覆盖保证。
- [x] 在相同位置、方向和质量模型下核对两条路线的 `q` 完全一致；输出覆盖缺口和诊断图。

当前 A1 遍历全部安全格中心，“路径约束”并不是稀疏骨架约束。改用骨架或改动扫描间距会改变候选空间，作为后续独立实验。

**A2 验收：** 用带物体的小场景人工/解析核对高度、安装偏移、视场边界、距离阈值、同站多方向及路径限制；所有输入物体保留在覆盖统计中，观察距离条件和未满足原因可追溯。A2 生成候选与预计覆盖，不输出未经 A3 求解的“最少锚点”。

## 后续顺序

- [x] **A3 主线选站：** 每个未覆盖物体对每站最多投一票，每轮选站后移除已完成目标的投票。先保持覆盖地删点，再减少拍摄方向；位置移动须重新验证路径、安全与质量。输出站位数、照片数、覆盖关系、缺口和求解状态。
- [x] **A4 首轮离线验证：** 候选生成对比固定路径、物体、质量模型和求解器，允许候选不同；求解器对比固定覆盖矩阵。报告候选规模、质量检查次数、耗时、覆盖、站位数与照片数，随机方法报告多种子波动，小案例用精确解核对。
- [ ] **B 静态真实实验：** 按锚点采集，独立检查实际图像质量并验证检索与找物。三维扫描的一站多方向、盲区补站作为参考，配准重叠仅在有实际需求时加入。
- [ ] **C 动态维护：** 物体分布变化后复核旧锚点，按需刷新记忆或补充站位，区分待采集和已采集状态。
- [ ] **D 长期评估：** 多轮变化、基线、消融与失败分析，再确定研究贡献。

## 当前运行入口

```bash
conda activate test
python -B falhv2/anchor_selector.py --scene falhv2/data/map.json --save-supports
```

默认固定读取 `data/map.json`、`data/robot.json`、`data/camera.d435i.json`，缺失时报错；其他输入必须显式指定。内部重算 A1，不要求起始位姿，也不直接复用可能过期的路径输出。结果为 `outputs/anchor_plan.json/.html/.svg`；支持矩阵另存为 `.supports.json`。HTML 可直接离线打开并导出当前地图 PNG。历史实验快照结果为 3 站、10 张照片、28/28 点覆盖；当前输出以实际输入为准。

## 下一步验收

1. 现场核对相机安装外参和 0.2–3 m 观察距离，按规划的站位与偏航采集照片，逐物体检查可见与可识别情况。
2. 获得可靠三维几何后加入遮挡判断，重点处理跨导航障碍的预计支持。
3. 在保持覆盖和站位数的情况下改进照片选择，再单独评估执行路线缩短与区域间转移。

八场景历史对比见[实验报告](anchor_driver_experiment_20261014.md)，复现多方法实验需切换至 `experiment/anchor-candidate-drivers`。主线只提供物体驱动；模型覆盖率不作为实测图像质量。

路径管理回归验收：在临时工作区删除 outputs 后，两次仅用 data 重新运行 A1 和锚点选择均成功；旧 outputs/map.json 不影响默认输入，输入文件保持不变。
