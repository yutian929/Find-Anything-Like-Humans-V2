# 真实机器人建图与锚点选择的代码架构

日期：2026-10-28。当前阶段：包结构整理与接口定义；真实建图尚未实现。

## 目标与边界

现有离线链路继续工作：地图 JSON → 安全区域 → 观察候选 → 两阶段选点 →
高密度复核 → JSON/HTML/SVG。默认 main.py 仍只执行这条链路。

真实建图的目标是持续生成同一 map 坐标系下的栅格地图与无类别物体 3D AABB。
规划器消费一个版本固定的地图快照，不直接读取设备、调用模型或查询在线 SLAM。
未来全流程由入口显式编排建图、冻结快照、选点，不能在求解过程中修改地图。

## 模块职责与依赖

- anchor_planners：现有规划算法；main.py 负责配置加载、CLI 和全流程编排。
- robot_adapters：将 ROS、厂商 SDK、录制数据转换成统一数据；运动控制另设 Navigator。
- model_clients：本地与远程实例分割，业务层只面向 InstanceSegmenter。
- map_maintainers：深度反投影、多帧关联、实例融合、生命周期、快照与规划导出。
- 数据结构归入所属模块的 base.py：robot_adapters 定义采集数据，model_clients 定义推理结果，map_maintainers 定义地图快照；导入这些接口不加载 ROS、相机 SDK、torch 或网络客户端。
- config：规划默认参数；后续 robot/model/map_maintainers 配置应分开。
- tools / assets：人工地图编辑、相机标定工具及页面。

数据流：

```text
RobotSource ── RGBDFrame ── InstanceSegmenter（local / remote）
     │             │                 │ SegmentationResult
     │             └─────────────────┴── MapBuilder
     └── GridSnapshot ────────────────────┘
                                          │ MapSnapshot
                                 校验 / 冻结 / 原子发布
                                          │ grid + objects JSON
                                  main.plan
```

已新增的 base.py 都是 Protocol，不能当作可运行的驱动或建图器。
本次不复制旧 anchor-map 模型代码，也不改动旧应用。

## 不同机器人如何适配

按通信栈实现适配器，按 profile 配置同栈的不同设备。profile 描述 adapter、
连接地址、图像/深度/栅格来源、map/base/camera frame、深度单位、标定、
同步容差和超时。机器人几何尺寸与安全距离仍是规划配置，不写死在驱动中。

RobotSource 的 open/capture/grid_snapshot/close 只负责数据。
Navigator 的 navigate_to/cancel 是可选能力。遥控采集和录制回放都能先完成建图，
无需先集成自动探索。未来自动探索应在独立任务编排层调用 Navigator，
不要塞进选点器或相机驱动。底盘原生避障、急停与导航失败由运动适配层保留。

RGB 与深度必须完成标定、去畸变、配准与时间同步。输出深度单位为米、
数值为光轴 Z，位姿使用采集时间而非模型返回时间。
明确 map/base 的前左上与光学坐标的右下前；矩阵 T_map_camera
满足 p_map = T_map_camera @ p_camera。失定位、无 TF、时间戳异常应拒绝本帧，
不能以单位变换或上一帧位姿悄悄代替。

二维栅格转换必须处理行方向、原点、分辨率、旋转和 unknown。
现有 planner 的第 0 行在顶部、原点在左下，未知格为 ?；
旋转地图须重采样到轴对齐栅格，不能忽略原点朝向。

## 本地与远程模型

同一模型模块可提供 Local / Remote 两个实现，由后续工厂按 backend + mode 选择。
local 配置权重位置、device；remote 配置 endpoint、timeout、协议版本。
本地 GPU 在另一台机器时，从机器人应用的角度仍是 remote。
重依赖延迟加载，配置错误或服务失败明确报错，不静默切换模型或自动下载。

统一输出原图尺寸的实例 mask、confidence、frame_id、model_id/version。
远程请求带帧 ID，响应必须匹配；图像缩放与 mask 解码留在客户端。
服务可用性、超时、有限重试、并发上限由客户端管理。使用有界队列，
避免推理慢时无界堆积旧帧；迟到结果依据帧 ID 与地图坐标版本处理。
认证信息来自环境或密钥存储，不写进地图快照。

不要求语义类别。模型提供实例候选，map_maintainers 用深度生成世界坐标下的几何。
旧 SAM2 客户端依赖提示框；旧 SAM3 接口依赖文本提示、返回 bbox。
它们不能直接替代自动无类别实例发现，需要选择合适能力并适配新的 mask 接口。

## 地图构建与维护

第一阶段复用机器人已有 SLAM 生成栅格，不同时自研 SLAM。
每帧 mask 内过滤无效深度、深度不连续与离群点，反投影后变换到 map。
单视角只能约束可见表面，AABB 是观测几何估计，不能当作完整真实物体尺寸。
遮挡严重或点数不足的实例保持 tentative，经过多视角证据再进入 confirmed。

关联使用空间重叠、点云距离及可选外观特征，维护稳定 object_id。
不能只对所有历史点累计 min/max，否则一次错误关联就会永久放大 AABB。
保留关键帧/局部点云证据，支持纠错、拆分、合并与重新估计。

区分 tentative、confirmed、stale、removed。单帧未检出不能证明物体消失；
只有定位可靠、该区域确实可观测且连续缺失，才累计负证据。
物体移动需关联为移动或新实例并使旧位置失效，不能把两处融合成大包围盒。
过期与暂定物体是否进入覆盖目标/遮挡模型必须有明确策略；
现有 planner 将所有 objects 同时当作目标与遮挡体，不能未经设计就静默混入
只用于遮挡的背景盒。栅格墙体目前也不会自动参与 3D 视线遮挡，后续需单独扩展。

SLAM 回环可能改变历史位姿。保存 map_id、SLAM 坐标修正版本与关键帧 ID，
在位姿图更新后重新变换并融合物体证据；旧 AABB 不能简单平移敷衍非刚性修正。
grid 与 objects 必须绑定同一坐标版本，版本冲突时停止发布，重建后再规划。

MapSnapshot 是一致性边界：内部保留状态、证据、时间戳和版本。
后续 export.py 将经过策略筛选的快照转换成现有 JSON：
grid 保留 rows/resolution/origin，objects 保留 id/position/aabb，
position 为 AABB 中心。快照 metadata 记录导出策略和源版本，
规划结果也应关联该版本。先校验、写临时文件，再原子发布，
不能让 planner 读到半份更新。地图变化后由上层显式触发重选，
本阶段不实现实时增量优化。

## 实施顺序与验收

1. 本次：移动现有模块、保持默认入口、回归验证；建立接口与设计文档。
2. 录制与 replay 适配器：确定第一台机器人的传感器、通信栈、SLAM/TF，
   录制少量同步数据，验证坐标、深度与时序；默认不自动运动。
3. 接入一个真正支持无类别实例输出的模型，实现 local 或 remote，
   再实现另一种部署；同一录制帧两种部署应遵守相同返回契约。
4. 离线构建 object map：先反投影与多视角关联，再做稳定 ID、异常过滤、
   生命周期和回环修正。用标注几何检验 AABB 与 ID，不能只看画面好不好看。
5. 实现快照存储与导出，复用现有选点流程，验证新地图能生成锚点。
6. 真机验证锚点可达性、导航、采图和实际可见性，随后再做在线更新与自动探索。

后续测试应覆盖：深度单位、行方向、旋转栅格、采集时刻外参、错帧响应、
模型掉线、定位丢失、遮挡时不误删、物体移动、SLAM 回环、版本一致性和
发布中断恢复。结构整理的验收记录见下节。
