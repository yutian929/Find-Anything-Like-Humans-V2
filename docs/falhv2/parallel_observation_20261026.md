# 逐物体并行观察实验（2026-10-26）

## 范围与环境

基线为 `30c1ebb`，包含 NumPy/GEOS 优化和 128 姿态批次。所有 Python 命令运行在同一个
`conda activate test` 环境，默认地图为 28 个目标、10,644 个安全站位、12 个朝向。
场景、相机、采样密度、阈值、MILP 和复核规则均不变。

先冻结基线到 `/tmp/falhv2-parallel-20261026/baseline-source/`，在线程/进程临时版本中逐目标评估，
确认收益与输出一致性后才修改正式代码。未恢复仓库中的 benchmarks 目录。

## 第一轮：线程与进程对照

每个目标一个任务；任务始终接收**完整场景**，不能只把目标传给观察器而丢掉其他遮挡体。
任务独立生成 supports、评分、诊断、计数；按原物体顺序合并，保持平局和输出顺序。

线程模式在整个线程池外围用 threadpoolctl 限制 BLAS 为 1 线程；进程模式使用 spawn，
每个工作进程初始化时限制 BLAS 为 1 线程。没有在各线程中分别进入全进程线程限制上下文。

下表是首轮独立实验脚本进程耗时，包含启动、规划、导出和结果对照；正式 main.py 计时另列。

| 模式 | workers | 候选生成（秒） | 实验进程（秒） | 输出一致性 |
|---|---:|---:|---:|---|
| 原串行 | 1 | 14.024 | 23.468 | 基线 |
| 串行，限制 BLAS=1 | 1 | 12.730 | 22.200 | 一致 |
| 线程 | 2 | 8.019 | 17.553 | 一致 |
| 线程 | 4 | 6.623 | 16.177 | 一致 |
| 线程 | 8 | 7.837 | 17.355 | 一致 |
| 进程 | 2 | 7.295 | 16.731 | 一致 |
| 进程 | 4 | 4.705 | 14.251 | 一致 |
| 进程 | 8 | 4.379 | 13.808 | 一致 |

这里的“一致”指完整候选 JSON（包含 supports/scores/热图）、最佳诊断、基线与最终 anchors、
覆盖和最优性字段，以及排除耗时的业务统计逐字段相等。所有版本均为 4 站10张，Float64 高密度复核通过。

线程不是越多越快：4 线程优于 8 线程。进程对 Python 部分的并行更充分，实测整体收益更大。
选择 **4 进程** 为默认；8 进程只再减少约 0.44 秒，却把进程数加倍。
这些结果不保证其他地图、CPU 或内存条件下仍有相同收益。

## 正式实现与回退

- 实现在现有 `anchor_candidates.py` 中；保留串行实现，公共入口负责调度和有序合并。
- 每个任务保留原来的全场景观察模型、目标索引、姿态顺序及失败诊断回算逻辑。
- 父进程先解析观察参数，再传给 spawn 工作进程，避免 API 调用时修改的默认参数在子进程中丢失。
- 主进程先验证输入；工作任务错误直接传播，不把缺少任务的结果当作完整覆盖结果。
- 空输入、零站位、单目标或 workers=1 不启动池；实际 workers 不超过目标数量。
- 多 worker 模式下 Open3D 内部线程设为 1，避免嵌套并行；默认射线仍为 NumPy Float64。
- 只并行候选阶段；MILP、原密度复核、高密度复核和导出保持原流程。
- `threadpoolctl==3.7.0` 已存在于 test 环境，现显式列入统一 requirements.txt。

```bash
conda activate test
# 默认 config.py：4 进程。
python -B falhv2/main.py
# 显式选择 4 线程。
python -B falhv2/main.py --observation-executor threads --observation-workers 4
# 立即回退到原串行计算；不创建任何池。
python -B falhv2/main.py --observation-workers 1
```

配置项是 `OBSERVATION_WORKERS=4`、`OBSERVATION_EXECUTOR='processes'`，CLI 优先。
`configuration` 保存请求配置；`statistics.candidate_workers/candidate_executor` 保存实际执行方式。
直接调用 `generate_candidates()` 默认仍为串行，可显式传 `workers` / `executor`；
`main.plan()` 默认读取项目配置，也支持 `observation_workers` / `observation_executor`。
独立 Python 脚本使用进程方式调用 API 时，应在 `if __name__ == '__main__':` 内启动；
交互式环境可使用线程方式或 workers=1。

## 验收

106 项 Python 测试通过，包含真实 spawn/线程输出一致性、保留所有遮挡体、父进程默认配置传递、
未覆盖目标诊断回算、非连续站位 ID 与选择顺序、旧点模型、无须创建池的边界情况、参数验证、任务异常传播。

按旧1→新1→旧2→新2→旧3→新3 串行、交替启动独立 Python 进程。
正式计时只包含 main.py 进程（包括启动、候选、MILP、复核和六个文件导出），结果比较在计时外执行。

| 正式版本 | 三次完整耗时（秒） | 完整中位数 | 候选中位数 |
|---|---|---:|---:|
| 30c1ebb 串行 | 23.189 / 23.116 / 23.193 | 23.189 | 13.965 |
| 默认 4 进程 | 13.862 / 13.859 / 13.733 | **13.859** | **4.711** |

完整运行减少 **40.23%**，加速 **1.673 倍**；候选阶段加速 **2.965 倍**。
剩余选择/复核阶段中位数 7.829 秒，没有对它宣称并行收益。

正式 CLI 的 4 线程单次为 **15.724 秒**（候选 6.650 秒）；`--observation-workers 1`
单次回退为 **23.124 秒**（候选 13.946 秒）。两条入口的结果也与基线逐字段一致。

验收范围：全部 supports、scores、热图、最佳物体诊断、基线与最终 anchors、覆盖和最优性字段，
以及排除耗时/并行元数据的统计字段完全一致。最终仍为 **4 站10张、28/28 覆盖**，高密度复核通过。
106 项 Python 测试和 2 套 Node 测试通过；第三轮默认并行输出已更新到 falhv2/outputs。
另对双物体小场景运行 Open3D 的串行/2 进程正式 CLI：实际启动 spawn 工作进程，
完整 supports、评分、诊断和最终方案一致，Float64 高密度复核通过。

机器可读结果见[逐次验收数据](parallel_observation_20261026.json)，包含环境、输入 SHA256、
探索实验和正式 CLI 各次计时/一致性检查。临时脚本与原始日志位于 `/tmp/falhv2-parallel-20261026/`。
