# 两阶段锚点选择：实现与默认地图验收

日期：2026-10-24。对应[修改计划](lexicographic_anchor_selection_plan_20261024.md)。本轮完成解质量优化和运行验证，尚未实施观察模型加速，未创建 Git 提交。

## 1. 最终结果

固定同一默认地图、相机、机器人、10,644 个安全格中心、30° 方向间隔和原观察门槛：

| 方案 | 锚点数 | 照片数 | 原观察模型覆盖 | 最终照片 96×96 复核覆盖 |
|---|---:|---:|---:|---:|
| 旧加权贪心 | 5 | 14 | 28/28 | 28/28 |
| 新两阶段优化，经过一次复核重选 | **4** | **10** | **28/28** | **28/28** |

减少 1 个锚点（20%）、4 张照片（约 28.6%）。原完整候选矩阵第一阶段目标和下界都是 4，第二阶段在 4 个锚点下目标和下界都是 10，两阶段 gap 均为 0。最终修正解仍是原矩阵的可行解，且成本相同，因此保持原候选池的字典序最优性。

“最优”限于当前离散站位、12 个方向和原观察模型。没有证明连续空间最优，也没有对所有候选重算 96×96 覆盖矩阵，因此不称为该高密度矩阵的全局最优。高密度采样仍不是无误差几何计算或真实可识别保证；导航路线与起点可达性仍不在本轮目标内。

## 2. 实现变化

- 新增 `falhv2/anchor_optimizer.py`：用已有 SciPy/HiGHS 求两阶段整数问题。第一阶段最少站位，第二阶段固定最优站数、允许重新选择全部站位和方向，求最少照片。保留逐物体合格约束；热图总分不再决定资源目标。
- `anchor_selector.py` 保留原加权贪心作独立基线；统一验证解的完整覆盖、站位/方向合法性及成本，处理限时、求解异常和几何复核失败。
- 输出 schema 5，保存成本对照、阶段界限和证明、旧基线、独立复核指标；候选 supports 继续使用 schema 4。
- 页面支持新方案与旧基线切换。新方案显示静态逐物体/叠加热图，旧方案保留自己的贪心轮次回放；最优性和高密度复核结果同时显示。
- 默认无求解时间上限。`--selection-time-limit-s` 限制全部整数求解调用，包括复核重选；观察计算、建模和复核不计入该 MILP 时间预算。

完整候选生成的 `observation_model.py`、`observation_region.py`、`regions_extractor.py` 和三个默认输入均未修改。最终导出的 supports、scores、逐物体热图、方向与站位数据和引入求解等价化简前的完整候选导出逐字段完全一致。

### 精确化简与模型增强

直接照片模型有 84,029 个变量。加入由整数可行性蕴含的站位覆盖约束后，完整模型独立取得 `(4,10)` 证明，照片阶段单次运行约 91.91 秒。

在求解副本中，同站去除被覆盖超集动作替代的照片；再按“全部极大动作覆盖集合组成的族”合并等价站位，得到 1,281 个代表站位、5,900 个代表动作。这个映射不会增加站位数或照片数，代表动作仍对应真实站位和朝向，保持当前字典序最优成本。不能仅按覆盖并集合并，也不能把该化简直接用于未来的路径、转向或质量奖励目标。

化简模型取得相同的 `(4,10)` 证明，并通过独立小实例穷举验证。以上耗时是开发过程中的单次观测，未作为严格性能基准。

## 3. 发现并修复的采样边界问题

首次最优解虽然在原矩阵中全覆盖，但 `station=2013, yaw_index=9, object=o14` 在 96×96 复核中失去合格性：

| 指标 | 原临界采样 36×36 | 独立 96×96 |
|---|---:|---:|
| 入镜比例 | 1.0 | 1.0 |
| 未遮挡比例 | 1.0 | 0.989583 |
| 最终观察得分 | 0.502468 | 0.497234 |
| 相同的 0.5 得分门槛 | 合格 | 不合格 |

该物体没有其他合格照片，首次方案的高密度覆盖只有 27/28。直接使用完整未化简模型得到的另一组最优动作也遇到同一关系的问题；这不是合并站位造成的信息损失，而是原采样遗漏少量遮挡。

代码现在默认对完整 AABB 的最终动作进行至少 96×96 检查。若覆盖出现缺口，仅在求解副本中删除已被复核否定的支持关系，然后重新选点。最多重选三次，且与初始求解共享时间预算；不能修复时退回经过高密度复核的基线。如果基线也未通过，明确记录失败，不宣称可靠覆盖。

本例删除该关系后，一次重选得到新的 `(4,10)` 解，最终 10 张照片 × 28 个物体共 280 个组合全部重新计算。原采样与 96×96 的合格分类 **0 次翻转**，共有 34 条合格观察关系，覆盖全部 28 个物体。额外独立重算与输出的高密度指标逐项一致。

主输出 `optimization.stage1/stage2` 保存原矩阵的证明；重选子问题的证明另存于 `optimization.high_density_verification.repairs`。只有最终成本等于原已证明成本，才能继承原池最优性；在删边子问题中证明最优但成本变大，不能据此宣称原池最优。该区别有专项测试。

## 4. 默认完整运行时间与站位

环境：conda `test`，Python 3.10、NumPy 1.26.4、SciPy 1.15.3、OpenCV 4.10。正式运行命令：

```bash
conda activate test
python -B -u falhv2/anchor_selector.py --save-supports
```

| 阶段 | 本次耗时 |
|---|---:|
| 安全区域与站位生成 | 0.037 s |
| 完整候选观察计算 | **56.584 s** |
| 初始站位 / 照片 MILP | 约 0.012 / 5.206 s |
| 重选站位 / 照片 MILP | 约 0.012 / 9.420 s |
| 选择阶段总计，含建模、基线、初次/基线/最终高密度审计及重选 | **16.133 s** |

前三个主要阶段合计约 72.75 秒，不含后续原模型最终复算和 JSON/HTML/SVG 导出，不能作为完整命令墙钟时间。观察阶段仍是主要耗时；本轮没有宣称它已经加速。
